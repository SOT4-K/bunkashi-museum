# 文化史ミュージアム（仮）— ゲーム設計書

作成 2026-09-03（Hayato）。オーナー要件は `../../LOG.md` 2026-09-03。変更は本書を更新し `../../decisions.md` に理由を書く。

## 1. コンセプト
- **一言**: 日本史の文化史を「作品を集めて自分の美術館を完成させる」ゲームで仕上げる。画像を見て答える → 正誤どちらでも全選択肢を画像付きで解説 → 間隔をあけて再出題 → 習熟した作品が美術館に「所蔵」される。
- **対象**: 大学受験の日本史を学ぶ高校生。特に日本大学付属校の「基礎学力到達度テスト」の受験者（形式・頻出テーマに寄せる。過去問は転載しない）。
- **範囲（MVP）**: 文化史のみ、飛鳥文化〜江戸（化政）文化まで。視覚作品（絵画・彫刻・建築・工芸・書）を優先。文学・学問・宗教など文章のみの項目は M2 以降。
- **到達目標**: 収録作品すべてについて「画像を見て作品名・時代（文化）・所在/作者を選択問題で完璧に答えられる」。
- **制約**: 無料・広告なし・アカウント不要・サーバーなし（静的 PWA）。個人情報を集めない。

## 2. 画面構成（iPhone アプリ風）
下部タブ 4 つ。上部にネイティブ風ヘッダー。ページ遷移はスライド、ボタンは 44pt 以上、システムフォント。

| タブ | 役割 |
|---|---|
| ホーム | 今日の学習（「復習 n 件＋新規 m 件」の 1 セッションボタン）、ストリーク、次の時代ボス、ホーム画面追加の案内（standalone でない時だけ） |
| 学習 | セッション画面。1 問 = 画像＋問題文＋4 択。回答直後に解説シート（下からスライド） |
| 図鑑 | 時代ごとのグリッド。未発見＝シルエット、発見＝カラー、所蔵＝額縁付き。タップで作品詳細（画像・解説・紛らわしい作品） |
| 成績 | 時代別の習熟率、正答率の推移、弱点作品トップ 10、模擬テスト（時代ボス／総合 20 問）への入口 |

- **standalone 判定**: `window.matchMedia('(display-mode: standalone)')` または `navigator.standalone`。false のとき、ホームに「ホーム画面に追加すると全画面で遊べます」の案内（iOS の手順：共有ボタン → ホーム画面に追加）。Safari 内で URL バーを消すことはできないため、これが唯一の「アプリ風」経路。
- **PWA 要件**: manifest（`display: standalone`, `theme_color`, アイコン 180/192/512）、`apple-mobile-web-app-capable`、`apple-mobile-web-app-status-bar-style: black-translucent`、`viewport-fit=cover` と `env(safe-area-inset-*)`、`100dvh`、`overscroll-behavior: none`、タップハイライト無効、ダブルタップズーム無効（`touch-action: manipulation`）。Service Worker でアプリ殻と作品画像をキャッシュ（オフラインでも遊べる）。
- **iOS の事実（2026-09 調査）**: ホーム画面 Web アプリは ITP の 7 日ストレージ削除の対象外（WebKit 公式）。iOS 26 からは manifest が無くても既定で Web アプリとして開く（実務記事複数、Apple 一次未確認）。スワイプで戻るジェスチャーは standalone でも無効化できないので、自前の画面遷移と二重に戻らないよう履歴の扱いを実装時に確認。アプリのスコープ外リンク（クレジットの出典 URL など）は簡易 Safari UI で開く。

## 3. 出題設計
### 問題型（MVP は Q1〜Q3。Q4 は M2）
- **Q1 画像→作品名**（主力）: 画像を見せ「この作品は？」4 択。
- **Q2 画像→文化（時代）**: 「この作品が作られた文化は？」（飛鳥／白鳳／天平／弘仁・貞観／国風／院政期／鎌倉／北山／東山／桃山／寛永期／元禄／化政）。
- **Q3 作品名→画像**: 作品名を示し、4 枚の画像から選ぶ（逆方向の想起。Q1 だけでは「名前を見て絵が浮かぶ」が鍛えられない）。
- **Q4 属性**（M2）: 作者・所在寺社・技法（乾漆／塑像／寄木造など）・様式（大和絵／水墨画など）。
- **出題画像はモノクロ**（オーナー決定 2026-09-03「写真は全て白黒で大丈夫」）。試験問題の図版はモノクロ印刷なので、出題時は CSS で白黒化して試験と同じ見え方で訓練する。解説シートと図鑑ではカラー（カラー画像がある作品）を見せる。仏像など戦前の白黒写真しか無い作品も、この方針で他と揃う
- 形式はすべて **4 択マーク式**（日大テストの形式に合わせる。詳細は `../../research/nichidai-test-format.md` の結果で調整）。

### 選択肢（ディストラクタ）の作り方
1. 作品ごとに手で書いた **紛らわしい作品（confusable）** を最優先で入れる（例: 風神雷神図屏風＝俵屋宗達 vs 尾形光琳の模写、鳥獣戯画 vs 信貴山縁起絵巻、興福寺阿修羅像 vs 十大弟子像）。
2. 残りは **同じカテゴリ（彫刻なら彫刻）かつ近い時代** からランダム。同一作品の重複・別名は除外。
3. 4 択の並びはシャッフル。正解位置の偏りを避ける。
4. 4 択の下に **「わからない」** を置く（5 番目の小さなボタン）。当てずっぽうで誤答選択肢を「正しい」と覚えてしまう negative suggestion effect（Roediger & Marsh 2005）への対策で、原論文が推奨する形。SRS 上は不正解扱い、XP は付かない、解説は同じく出す。

### 解説（Must 要件）
回答直後に、正誤にかかわらず解説シートを出す。構成は固定：
1. **判定**（正解／不正解＋選んだもの）。不正解のときは先頭に「なぜ違うか」を 1 文（例：「これは十大弟子像。僧の姿で腕は 2 本」）
2. **正解の作品**: 画像・作品名（読み）・文化・所在/作者・技法・**押さえるポイント 2〜4 個**・解説文（3〜6 文）
3. **他の 3 つの選択肢**: それぞれ画像＋作品名＋文化＋1〜3 文の解説＋**「見分け方」**（紛らわしい理由と着眼点。例：「阿修羅像は三面六臂、十大弟子像は一面二臂の僧形」）
4. **入試での注意点**（あれば。例：「『天平文化』と『白鳳文化』の区別で問われやすい」「作者名は宗達／光琳どちらの図か」）
5. 「図鑑に追加」演出（初回正解時）

## 4. 定着の設計（学習科学に基づく。詳細は `../../research/learning-science-and-pwa.md`）
- **間隔反復（SRS）**: 作品×方向（画像→名前／名前→画像／画像→文化）ごとに箱 0〜5。正解で 1 つ上、不正解で 0 に戻す。間隔は 0/1/3/7/14/30 日。箱 4 以上を「習熟」とし、3 方向とも習熟で「所蔵」。Leitner 式の固定間隔にする理由: FSRS/SM-2 のような統計フィッティングはユーザーあたり約 1000 レビューが必要で、サーバーなし・少レビューの本アプリでは効かない（research/learning-science-and-pwa.md A3）。6 段階の値は経験則で、実証された最適値ではない。
- **想起練習**: 見せて覚える画面は作らない。必ず問題として出す（図鑑は復習用に閲覧可）。
- **誤答の即時再出題**: 間違えた作品はそのセッションの後半でもう一度（型を変えて）出す。
- **交互配置**: 1 セッションに同じ時代を並べず、近い時代・同カテゴリを混ぜる（識別力を上げる）。
- **セッション設計**: 1 セッション 10 問（約 3 分）。構成＝復習期限の来た作品を優先（最大 7）＋新規（残り、上限 5）。1 日に何セッションでもよいが、新規は 1 日 15 作品まで（詰め込み防止）。
- **紛らわしいペアの集中出題**: 一方を間違えたら、次のセッションでペアの両方を続けて出す（知覚学習の「似た事例の比較提示」に一致。Kellman らの PLM 研究）。

## 5. 楽しさの設計
- **図鑑＝美術館**: 発見（初正解）でシルエットがカラーになり、所蔵（習熟）で額縁が付く。時代ごとの「展示室」が完成すると演出。
- **XP とレベル**: 正解 10XP、復習正解 15XP、時代ボス突破 200XP。レベルに応じた称号（見習い学芸員 → 学芸員 → 主任学芸員 → 館長）。
- **ストリーク**: 連続学習日数。1 セッションで達成。途切れそうな日はホームに表示（通知は M2 以降で検討。PWA の通知は iOS 16.4+ の standalone のみ）。
- **時代ボス**: 時代の作品を 60% 以上「発見」すると解放。20 問、90% 以上でクリア。クリアで展示室に「認定バッジ」。
- **テスト直前モード**（M2）: 全時代ランダム 20 問／苦手だけ 20 問。日大テスト形式に寄せた模擬。
- **軽さ**: 起動 1 秒以内、1 問 20 秒以内、セッション 3 分。通学の電車で 1 セッション。

## 6. データモデル
### 作品（`content/works/<era>.json`、配列）
```json
{
  "id": "ashura-kofukuji",
  "title": "阿修羅像",
  "reading": "あしゅらぞう",
  "era": "tenpyo",
  "category": "sculpture",
  "location": "興福寺（奈良）",
  "author": null,
  "technique": "脱活乾漆像",
  "keyPoints": ["天平文化", "興福寺八部衆の一つ", "三面六臂", "脱活乾漆"],
  "explanation": "……3〜6 文……",
  "examNote": "……入試での注意点（任意）……",
  "confusables": [
    { "id": "judai-deshi-kofukuji", "howToTell": "十大弟子像は一面二臂の僧形。阿修羅は三面六臂" }
  ],
  "image": { "file": "ashura-kofukuji.webp", "credit": "…", "license": "CC BY 4.0", "sourceUrl": "…", "sourceName": "ColBase" },
  "sources": ["山川『詳説日本史』p.xx", "興福寺公式サイト …"],
  "examTags": ["nichidai-frequent"],
  "status": "draft | reviewed"
}
```
- `era` の一覧は `content/eras.json`（id, 名称, 時代区分, 順序, 一言説明）。
- `category`: architecture | sculpture | painting | craft | calligraphy | garden | other。
- `status: reviewed` の作品だけを本番ビルドに含める（reviewer の事実検証を通ったもの）。
- 画像は `content/images/<id>.webp`（長辺 1200px 以下、100KB 目安）。ライセンスは `content/images/manifest.json` に **全件** 記録（file, sourceUrl, license, credit, retrievedAt）。アプリ内の「クレジット」画面に自動で一覧表示。

### 進捗（localStorage、キー `bunkashi.v1`）
```json
{
  "version": 1,
  "xp": 0, "level": 1, "streak": {"count": 0, "lastDate": "2026-09-03"},
  "items": { "<workId>": { "q1": {"box": 0, "due": "2026-09-04", "correct": 0, "wrong": 0}, "q2": {...}, "q3": {...}, "discoveredAt": null, "masteredAt": null } },
  "bosses": { "<eraId>": { "cleared": false, "bestScore": 0 } },
  "newToday": {"date": "2026-09-03", "count": 0}
}
```
- スキーマ変更時は `version` を上げ、移行関数を用意（古い進捗を消さない）。
- エクスポート／インポート（JSON をコピー）を成績画面に置く（端末変更対策。サーバーなしの代替）。

## 7. 技術
- Vite + React + TypeScript、`vite-plugin-pwa`（workbox。アプリ殻は precache、画像は runtime cache）。ルーティングはハッシュ不要な軽量ルーター（`wouter` 等）か自前の state。状態は React の `useReducer` + localStorage。
- スタイルは CSS Modules または素の CSS。UI ライブラリは入れない（iOS 風の見た目を自前で。ダークモード対応は `prefers-color-scheme`）。
- テスト: 出題生成（ディストラクタ選択・シャッフル）と SRS（箱・期日）は純関数にして Vitest で単体テスト。
- ビルド時に `content/` を検証（`scripts/validate-content.ts`: 必須項目・confusable の参照先の存在・画像の存在・ライセンスの記録）。検証に失敗したらビルドを止める。
- パフォーマンス: 初回ロード < 300KB（画像除く）。画像は WebP。Lighthouse PWA 合格。
- 公開: `DEPLOY.md`（GitHub Pages を第一候補。`base` パスの設定に注意）。

## 10. 設問型の拡張（2026-09-03 オーナー指示。research/question-formats.md で確定）
研究の結論: 共通テストの図版問題は「画像→作品名」の単純想起ではなく、**図版を入口に関連記述の正誤・同時代事項の組合せ・時期の整合を問う**。オーナー仮説は裏付けられた。優先順位は **Q4（関連記述の正誤）→ Q6（同時代事項の組合せ）→ Q8（組合せ文）**。Q5（作者・技法）・Q7（年代整序）は試験での実例が確認できなかった「拡張機能」として位置づけ、⑨「図版＋別資料（メモ・史料）の整合性判断」は最も試験に近いが実装コストが高いため M2 以降。既存の Q1〜Q3 は「見分ける力」の基礎練習として残す（初学者向けに山川図版問題集型の 2 択モードも候補）。
オーナーの要件: 「画像→作品名」だけでなく、**画像を入口に時代・文化・作者・関連事項を選ばせる**日大テスト型。例: 平等院鳳凰堂の写真 →「この建築物に関連する記述として正しいものを選べ」→ 藤原頼通の建立（正）／聖武天皇の建立／禅宗様の代表／東大寺大仏殿と同じ天平文化。

### 設問型（案）
| 型 | 問い | 選択肢 | データ源 |
|---|---|---|---|
| Q1 | 画像→作品名 | 作品名 4 | 既存 |
| Q2 | 画像→文化 | 文化名 4 | 既存 |
| Q3 | 作品名→画像 | 画像 4 | 既存 |
| **Q4 関連記述** | 画像→「この作品に関する記述として正しいもの」 | 文 4（正 1・誤 3） | `facts`（正しい文の部品）＋他作品の同スロットの値でずらした誤文 |
| **Q6 同時代の事項** | 画像→「この作品と同じ文化に属する事項」 | 事項 4（文学・宗教・人物など） | `eras[].items`（文化ごとの代表事項リスト） |
| **Q8 組合せ文** | 画像＋2 つの観点→「①頼通・浄土教 ②頼通・禅宗 ③道長・浄土教 ④道長・禅宗」のように選択肢自体を組合せ文にする（共通テストの現行形。「正正／正誤」ラベルは使わない） | 4 | `facts` の 2 スロットと他作品の値 |
| Q5 作者・技法・所在（実例未確認） | 画像→「作者／技法／所在は」 | 名前 4 | `artist` / `technique` / `location` |
| Q7 複数画像の比較（実例未確認） | 3 枚の画像→「古い順」「作品と文化の組合せ」 | 順列/組合せ 4 | `eras[].order` と作品の era |
| ⑨ 図版＋別資料（M2 以降） | 画像＋短いメモ/史料→「メモの内容と図版の時期が整合するもの」 | 4 | 未設計 |

### 誤文の作り方（Q4・Q8）。「うっかり正しい文」を作らないための規則
- 正文は **スロット付きテンプレート**から生成する: 「{patron}が建立した」「{artist}の作」「{style}を代表する」「{era}の作品」「{location}にある」「{technique}で作られた」「{religion}の思想を背景に持つ」
- 誤文は **同じスロットに他の作品の値を入れる**。ただし (a) 値が同じなら使わない (b) 当該作品にも当てはまる値（例: 「乾漆像」は阿修羅・十大弟子どちらも真）は `facts` に「別解」として登録し除外 (c) 生成した誤文は writer/reviewer が一度目視して `verifiedFalse: true` を付けたものだけ本番に出す
- ずらしの優先順位（試験の常道）: 時代ずらし（天平↔白鳳）→ 人物ずらし（頼通↔道長）→ 様式ずらし（禅宗様↔大仏様）→ 所在ずらし

### 解説の拡張（オーナー要件④）
- 各作品の解説の先頭に **「時代と文化」の 2〜3 文**を置く: 「奈良時代（8 世紀）、聖武天皇のころに栄えた天平文化の彫刻。天平文化は遣唐使が伝えた唐の様式を受け、鎮護国家の思想のもとで…」。`eras[].detail`（時代の説明）＋作品側 `eraNote`（その作品と時代の結びつき）
- 続けて既存の explanation（作品そのもの）→ keyPoints → 見分け方 → 入試での注意点

### データ構造の追加（案）
```json
// works: 追加フィールド
"artist": "定朝" | null,          // 正規化した作者（Q5）。author は表示用に残す

"style": "寄木造・和様" | null,    // 様式
```
